## 🚨 PART 1: CRITICAL BUG FIXES

### BUG 1: ProviderNotFoundException — ScannerBloc Missing Dependencies

**Error:**
```
Bad state: Tried to read a provider that threw during the creation of its value.
The exception occurred during the creation of type ScannerBloc.
ProviderNotFoundException: Could not find the correct Provider<ScanLabelUseCase>
above this ScannerPage Widget
```

**Root Cause:** `ScannerBloc` requires `ScanLabelUseCase` via constructor injection, but `ScanLabelUseCase` is NOT registered in the `MultiProvider` tree above `ScannerPage`.

**FIX — Step-by-Step:**

#### Step 1: Ensure ALL UseCases are registered in DI (get_it)

In `lib/core/di/injection.dart`:
```dart
import 'package:get_it/get_it.dart';
import 'package:injectable/injectable.dart';

final getIt = GetIt.instance;

@InjectableInit()
void configureDependencies() => getIt.init();
```

In `lib/core/di/injection.config.dart` (auto-generated by injectable):
Make sure ALL these are registered:
```dart
// UseCases
getIt.registerLazySingleton<ScanLabelUseCase>(() => ScanLabelUseCase(getIt<ScannerRepository>()));
getIt.registerLazySingleton<GetLabelDetailsUseCase>(() => GetLabelDetailsUseCase(getIt<ScannerRepository>()));
getIt.registerLazySingleton<GetPatientsUseCase>(() => GetPatientsUseCase(getIt<UsageRepository>()));
getIt.registerLazySingleton<RecordUsageUseCase>(() => RecordUsageUseCase(getIt<UsageRepository>()));
getIt.registerLazySingleton<LoginUseCase>(() => LoginUseCase(getIt<AuthRepository>()));
getIt.registerLazySingleton<GetCurrentUserUseCase>(() => GetCurrentUserUseCase(getIt<AuthRepository>()));
// ... ALL other use cases
```

#### Step 2: Wrap ScannerPage with MultiProvider at the ROUTE level

In `lib/core/router/app_router.dart` (or wherever routes are defined):
```dart
GoRoute(
  path: '/scanner',
  builder: (context, state) {
    return MultiProvider(
      providers: [
        // Provide the UseCase FIRST
        Provider<ScanLabelUseCase>(
          create: (_) => getIt<ScanLabelUseCase>(),
        ),
        Provider<GetLabelDetailsUseCase>(
          create: (_) => getIt<GetLabelDetailsUseCase>(),
        ),
        // Then provide the BLoC (which depends on the UseCases)
        BlocProvider<ScannerBloc>(
          create: (context) => ScannerBloc(
            scanLabelUseCase: context.read<ScanLabelUseCase>(),
            getLabelDetailsUseCase: context.read<GetLabelDetailsUseCase>(),
          ),
        ),
      ],
      child: const ScannerPage(),
    );
  },
),
```

**CRITICAL RULE:** The order of providers in `MultiProvider` matters. Provide dependencies BEFORE the widgets that consume them. `ScannerBloc` must be listed AFTER `ScanLabelUseCase`.

If you want BLoCs to be global (accessible everywhere):

**BUT** — if using global BLoCs, make sure `ScannerBloc` constructor does NOT do heavy work in `create`. Use `lazy: false` only if needed.

In `lib/features/scanner/presentation/bloc/scanner_bloc.dart`:

    return AppColors.success;

  IconData _getStatusIcon(Label label) {
    if (label.isExpired) return Icons.error_outline;
    if (label.isRecalled) return Icons.warning_amber_rounded;
    if (label.alreadyUsed) return Icons.info_outline;
    return Icons.check_circle_outline;
  }

  String _getStatusTitle(Label label) {
    if (label.isExpired) return 'Instrument Expired';
    if (label.isRecalled) return 'Instrument Recalled';
    if (label.alreadyUsed) return 'Already Used';

  String _getStatusMessage(Label label) {
    if (label.isExpired) {
      return 'This instrument has exceeded its expiration date and cannot be used.';

    if (label.isRecalled) {
      return 'This instrument has been recalled for safety reasons.';
    }
    if (label.alreadyUsed) {
      return 'This instrument has already been recorded as used.';

    return 'Sterilization cycle passed. Safe to use.';

### 🔑 Key Principle: "The Admin is the Root"

**Only the Administrator can create accounts.** This is how it works in the real world:

1. **Dental practice owner** (or IT manager) = Administrator
2. Admin logs into the **Web Admin Panel** (React/Next.js)
3. Admin creates accounts for:
   - Receptionist/Assistant → Role: `assistant`
   - Dr. Martin, Dr. Dubois → Role: `practitioner`
4. Each user receives an email with login credentials
5. Users download the mobile app and log in
6. The app reads their role from `GET /api/v1/auth/me` and shows the correct UI

### 🚫 What Each Role CANNOT Do

|--------|-------|-----------|--------------|
| Create user accounts | ✅ | ❌ | ❌ |
